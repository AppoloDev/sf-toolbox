# Csv, HTTP Responses, Email Message, Twig, Utils

## Csv (`AppoloDev\SFToolboxBundle\Csv\CsvWriter`)

Thin wrapper over `league/csv`'s `Writer`. Defaults: `;` delimiter, UTF-8 BOM output (Excel-friendly). Fluent: `setDelimiter()`, `setHeaders(array $headers)`, `setRow(array $row)`, `setRows(array $rows)` all return `self` except `setDelimiter` (void); `getContent(): string` returns the full CSV text. Typical use: feed the result straight into `CsvFileResponse`.

## HTTP Responses (`AppoloDev\SFToolboxBundle\Response\*`)

- `CsvFileResponse(?string $csvContent = '', string $fileName = 'export.csv', int $status = 200, array $headers = [])` — a `Response` with `Content-Type: text/csv` and `Content-Disposition: attachment` pre-set. Typical pairing: `new CsvFileResponse((new CsvWriter())->setHeaders([...])->setRows($rows)->getContent(), 'books.csv')`.
- `ZipResponse(File[] $files, string $zipName = 'export.zip', int $status = 200, array $headers = [], bool $public = true, ...)` — builds a real temp zip file (`sys_get_temp_dir()`, via `ZipArchive`) from an array of `Symfony\Component\HttpFoundation\File\File`, then serves it as a `BinaryFileResponse` with the attachment disposition already set. Throws `FileException` if the zip can't be created.

Both are natural fits for the `Export<Entity>Controller` stub generated by `make:scaffold` ([maker-commands.md](maker-commands.md)).

## Email (`AppoloDev\SFToolboxBundle\Message\EmailMessage` + `MessageHandler\EmailSenderHandler`)

A Symfony Messenger message/handler pair for sending templated emails asynchronously.

`EmailMessage(array $recipients, string $object, string $template, array $parameters = [], string $locale = 'en', array $files = [], ?string $logoPath = null)` — `$recipients` are plain email strings (converted to `Address` internally), `$object` is a **translation key** (translated against the `emails` domain by the handler, not a literal subject string), `$template` is a Twig template path for `TemplatedEmail::htmlTemplate()`, `$parameters` become the Twig context (with `locale` auto-merged in), `$files` is a list of `['file' => <object with getContent()>, 'filename' => string]`.

Dispatch it through the Messenger bus like any other message: `$bus->dispatch(new EmailMessage(['user@example.com'], 'welcome.subject', 'emails/welcome.html.twig', ['name' => $name]));`

`EmailSenderHandler` (`#[AsMessageHandler]`, autowired) builds a `TemplatedEmail`, embeds a logo image (`$emailMessage->getLogoPath()` if set and the file exists, else falls back to `%kernel.project_dir%/public/assets/images/logo.png` — **that fallback path must exist in the consuming project**, or provide `logoPath` explicitly) as inline `cid:logo`, and sends via `MailerInterface`. Requires two env vars in the consuming project: `SENDER_EMAIL`, `SENDER_NAME` (bound via `#[Autowire('%env(...)%')]`). Translation of the `emails` domain — the bundle ships base translations in `translations/messages.{en,es,fr}.yaml` for its own use; add your own subject keys to the consuming project's own `translations/emails.*.yaml` (or `messages.*.yaml` if that's the domain used) as needed since `object` is translated in the `emails` domain specifically.

## Twig (`AppoloDev\SFToolboxBundle\Twig\Extension\IntlExtension`)

Adds one filter: `localizedDate(\DateTime $date, ?string $format = null, string $locale = 'fr-FR'): string` — formats via PHP's `IntlDateFormatter` (`FULL`/`FULL`, timezone hardcoded to `Europe/Paris`), then `ucwords()`s the result. Usage: `{{ someDate|localizedDate('d LLLL', 'fr') }}`. `$format` is an ICU pattern (see the [ICU date/time format docs](https://unicode-org.github.io/icu/userguide/format_parse/datetime/)).

## Utils (`AppoloDev\SFToolboxBundle\Utils\*`, all static-method-only classes)

- `UuidUtils::isUuid(string $value): bool` — `true` if `$value` parses as a `Symfony\Component\Uid\Uuid`. Used pervasively by the repository Criteria layer to auto-detect UUID params ([repository-criteria.md](repository-criteria.md)).
- `ArrayUtils::recursiveFind(?array $haystack, string $needle): mixed` — depth-first search for a key named `$needle` anywhere in a nested array, returns its value or `null`. `ArrayUtils::flatten(array $array): array` — recursively flattens nested arrays into a single flat list of scalar leaves.
- `GeocompleteUtils::transformGeocompleteData(string $geocompleteJson): array` — parses a Google-Places-shaped geocomplete JSON payload (`formattedAddress`, `location.{lat,lng}`, `addressComponents[].{types,longText}`) into a flat array with keys `formattedAddress`, `lat`, `lng`, and (if present in `addressComponents`) `city` (from `locality`), `zipCode` (from `postal_code`), `country`. This is the parser behind `GeolocalizableSubscriber` and `GeolocalizableConstraintValidator` ([form-types.md](form-types.md)) — the JS widget on the frontend must emit JSON in this exact shape.

## Bundle wiring (`SFToolboxBundle`, `DependencyInjection\SFToolboxExtension`, `config/services.yaml`)

- `SFToolboxBundle extends AbstractBundle`; its extension (`SFToolboxExtension`) loads `config/services.yaml` and, via `PrependExtensionInterface`, prepends config into the **consuming app's own** `twig` and `framework` extensions:
  - If `TwigBundle` is present: adds Twig globals `siteTitle`, `themeColor`, `googleMapApiKey` — bound to env vars `SITE_TITLE`, `THEME_COLOR`, `GOOGLE_MAP_API_KEY`, which the consuming project must define (`.env`/`.env.local`) or these globals resolve to unset env errors.
  - Always sets `framework.router.default_uri` from env var `DEFAULT_URI` — also required in the consuming project's env.
- `services.yaml`: autowires/autoconfigures everything under `src/` except `DependencyInjection/`, `Domain/Entity/`, `Domain/Repository/` (traits/base classes, not services). `IsNotGrantedAttributeListener` is wired explicitly with `security.authorization_checker` and `security.is_granted_attribute_expression_language`.
